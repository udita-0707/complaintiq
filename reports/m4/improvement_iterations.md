# M4 improvement iterations (validation split)

Generated by `python -m complaintiq.models.iterations` (`make iterations`). Each iteration = hypothesis, change, result, logged in `reports/experiments/m4/iterations.csv` (val_* columns there are val-B).

- Base: the primary model `baseline/tfidf_sgd_alpha2e-6_conv`, argmax, no calibration.
- Every choice is made on **val-A** (93848 rows); **val-B** (93850 rows) is held out. The test split was not read. Adopt = better val-A macro-F1 than the base.
- Nothing here changes the primary model or the serving path; adopting an iteration is a team decision before the freeze (configs/final_model.yaml).
- Each iteration is measured alone against the same base. **TODO:** their combination (e.g. class weights ** 0.5 + prior correction + issue restriction) was not run; the gains may overlap. Adopting any of them also requires re-running `make calibrate` (temperature and tau were fit on the base model's probabilities).

## Iteration 1: prior correction for the label shift

**Hypothesis.** Balanced class weights make the model act as if classes were equally frequent, but val is dominated by credit reporting (product share 0.405 in train vs 0.605 in val; issue `Improper use of your report` 0.063 vs 0.177, M2 report section 3). Multiplying the probabilities by the class prior should recover accuracy and weighted-F1; the effect on macro-F1 is uncertain.

**Change.** `p'(y|x) ~ p(y|x) * prior(y) ** lambda`; prior from train labels or val-A labels; lambda in [0.0, 0.25, 0.5, 0.75, 1.0]; best by val-A macro-F1.

## Iteration 2: class-weight tuning

**Hypothesis.** M3 showed balanced weights lift macro-F1 over no weights (product 0.771 vs 0.737, issue 0.487 vs 0.402 at alpha 1e-5, reports/m3/model_comparison.md) but may over-predict small classes. A softer weighting (balanced ** power) could keep the minority-class recall and recover precision.

**Change.** Retrain product and issue on all of train with the primary model's saved vectorizer and classifier settings, class weights balanced ** power, power in [0.5].

**Result.**

| task | power | val-B macro-F1 base -> new | val-B weighted-F1 base -> new | val-A macro-F1 base -> new | n_iter / converged | adopt | run_id |
|---|---|---|---|---|---|---|---|
| issue | 0.5 | 0.5046 -> 0.5282 | 0.6120 -> 0.6296 | 0.5091 -> 0.5318 | 23 / True | True | `249d8fab2bad` |
| product | 0.5 | 0.7823 -> 0.7940 | 0.8786 -> 0.8844 | 0.7815 -> 0.7907 | 22 / True | True | `fe3d78b26130` |

## Iteration 3: issue restricted to the predicted product

**Hypothesis (measured).** Of 73,307 issue errors on val, 0.3105 predict an issue never (or rarely) seen with the true product in train. The product model is much stronger than the issue model, so forcing issue to agree with the predicted product should remove some of them.

**Change.** Zero the probability of issues seen with the predicted product in fewer than 20 training rows, then renormalize (70 of 340 product-issue pairs allowed).

**Result.**

| val-b | 0.5046 -> 0.5191 | 0.6120 -> 0.6219 | 0.8672 -> 0.8660 |

Adopt: True (run_id `5a1b45561c8c`).
